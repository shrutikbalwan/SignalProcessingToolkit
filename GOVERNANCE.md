# Governance

SignalProcessingToolkit is maintainer-led and community-driven. Maintainers
review pull requests, protect the default branch, manage releases, and may
delegate subsystem ownership. Technical decisions should be documented in
`docs/adr/` when they affect public APIs, scientific behavior, security, or
packaging.

Changes require review from at least one maintainer. Breaking changes require
an issue, migration notes, tests, and a changelog entry. Releases are tagged by
a maintainer only after the checklist in `docs/release-checklist.md` passes.

The project follows the MIT license and the Code of Conduct. Governance may be
updated through a reviewed pull request.
